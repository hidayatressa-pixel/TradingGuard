# TradingGuard V0.9 — Paper Stop Execution Specification

## Purpose

Make the risk-at-stop used by Risk Sizing operationally meaningful in Paper Trading without enabling live broker execution.

## Locked semantics

1. Long-only for V0.9.
2. A prospective entry must carry an authoritative stop-loss price produced/validated before Risk Guard evaluation.
3. The stop is copied into the pending entry and then into the open paper position. It must not be invented by the frontend or reconstructed from allocation.
4. Stop-loss is a reduce-risk exit. It does not require a new Risk Guard ALLOW decision.
5. Stop evaluation happens only after a position already exists. A position opened at the current candle OPEN must not use that candle's earlier HIGH/LOW path to trigger a stop; doing so would introduce intrabar lookahead/path ambiguity.
6. For a position carried into a candle:
   - if candle OPEN <= stop, the stop is gap-through and the base stop fill is candle OPEN;
   - otherwise, if candle LOW <= stop, the base stop fill is the stop price;
   - otherwise no stop exit occurs.
7. Adverse exit slippage is applied to the base stop fill using the existing paper slippage percentage: effective exit = base fill * (1 - slippage_pct/100).
8. Existing transaction cost is charged on the exit notional. Entry fee remains part of total realized P/L.
9. A stop exit has priority over scheduling a strategy exit on the same candle. Existing already-pending exits that execute at the current OPEN keep their V0.7 next-open priority.
10. Gap-through losses may exceed the planned price risk. TradingGuard must report realized P/L truthfully and must never claim the configured risk budget is guaranteed.
11. Risk Sizing V0.9 currently reports price risk to the proposed stop only; fees, slippage, and gap risk are not included in `risk_per_trade_pct`. Until a later conservative all-in risk model is implemented, UI/docs must disclose this limitation.
12. No live orders, broker credentials, leverage, shorts, trailing stops, or automatic real-money execution are introduced here.

## Required model additions

- `PendingEntry.stop_loss_price`
- `PaperPosition.stop_loss_price`
- `PaperTrade.exit_reason` with at least `STRATEGY` and `STOP_LOSS`

## Required safety tests

- stop is persisted from pending entry to position;
- carried position stops at stop price when LOW breaches without gap;
- gap-through fills from OPEN, never optimistically at stop;
- adverse slippage and fees are charged;
- stop exit does not require Risk Guard ALLOW;
- a newly opened position cannot stop on the same candle from historical LOW;
- stop takes precedence over new strategy-exit scheduling;
- V0.7 next-open strategy execution semantics remain unchanged;
- all existing regression tests remain green.

## Activation gate

Paper BUY must remain disconnected from the new prospective Risk Gate until this stop execution behavior, API orchestration, and end-to-end tests pass. This specification alone does not authorize Paper BUY.
