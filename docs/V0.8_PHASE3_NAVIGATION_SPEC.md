# TradingGuard V0.8 — Phase 3 Operational Navigation

Status: DESIGN LOCK

## Goal

Turn the V0.8 dashboard shell into navigable operational views without weakening the backend-authority boundaries established in Phases 1 and 2.

## Navigation

The sidebar will expose these application views:

1. Dashboard
2. Market
3. Strategy
4. Risk Guard
5. Paper Trading
6. Backtest
7. Trade Journal
8. Settings

Navigation is a presentation concern only. Changing views must not execute a trade, start/reset/process a paper session, or manufacture a risk decision.

## View contracts

### Dashboard

Keep the existing integrated overview. Market/indicator/strategy values come from backend routes. Paper values are read-only when a process-local session exists. Risk permission remains unavailable until authoritative context exists.

### Market

Show backend-sourced OHLCV and technical indicator information. No browser-generated candles and no local indicator calculations.

### Strategy

Show backend `StrategyResult`, normalized score, readiness, assessment, and evidence. Explicitly state that market condition is not execution permission.

### Risk Guard

Show the current V0.8 authority state truthfully:

- Risk context: UNAVAILABLE / INCOMPLETE
- Execution permission: UNAVAILABLE
- Reason: Awaiting authoritative risk context

Do not fabricate a `RiskResult`. Do not call `/risk/evaluate` with guessed values. Do not map paper `position_size_pct` to `risk_per_trade_pct`.

### Paper Trading

Read-only in Phase 3. Show authoritative backend account/performance when a session exists. If not started, show a clear NOT STARTED state. Do not auto-start, reset, or process paper trading from navigation or page load.

### Backtest

Phase 3 may make the existing V0.6 backtest engine operable through an explicit user action, provided inputs are backend-sourced and aligned. React must not calculate strategy or performance locally. The result displayed must be exactly backend `BacktestResult` data.

Before POST `/backtest/evaluate`, validate that the already-fetched candle and strategy arrays have equal length and matching timestamp/symbol/timeframe at every index. Alignment failure must prevent the request and show an error; it must not repair or guess the sequence.

Running a backtest is simulation only and must not mutate paper state.

### Trade Journal

Show backend `PaperAccount.closed_trades` only. No synthetic rows.

### Settings

Display integration/runtime information only in V0.8 Phase 3: API base URL, current simulated-data disclosure, and safety boundaries. Do not add broker credentials or live execution controls.

## Safety invariants

- MARKET CONDITION != EXECUTION PERMISSION.
- Unknown risk != zero risk.
- Allocation != risk per trade.
- Frontend never becomes a second Strategy/Risk/Paper/Backtest engine.
- Navigation is non-mutating.
- Paper remains virtual and process-local.
- No broker connection or real-money order execution.

## Phase 3 acceptance gates

- Every sidebar item opens a meaningful view.
- Market and Strategy are backend-sourced.
- Risk Guard truthfully remains unavailable/fail-closed.
- Paper Trading and Trade Journal are backend read-only.
- Backtest, if enabled, is explicit user-triggered and backend-calculated only.
- Settings contains no credentials or live trading controls.
- No page load causes paper mutation.
- Existing 102 backend regression tests pass.
- Frontend production build passes.
- Frontend lint passes with zero errors.
- `git diff --check` passes.
- Human visual review passes before V0.8 final release.
